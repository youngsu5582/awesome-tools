# intake — 공고에서 시작하는 지원 프로필

공고 한 장을 **이후 단계(이력서 · 시험 대비 · 면접)가 계속 꺼내 쓰는 프로필**로 바꾼다.
요약이 아니라, 다음 단계가 질문할 거리를 남기는 정리다.

> **확인한 것 · 추정 · 미확인을 섞지 않는다.**
> - **확인** — 공고 · 공식 자료에서 직접 읽은 문장. 출처를 단다
> - **추정** — 공고를 근거로 미루어 본 것. `추정` 이라고 쓴다
> - **미확인** — 열어 보지 못했거나 출처를 못 찾은 것. `미확인` 이라고 쓴다
>
> 확인할 수 있는 건 실제로 확인한다 — 링크를 열어 공고 원문과 대조하고, 회사 블로그 · 발표가 실제로 있는지 본다. 기억으로 채우지 않는다.
> 페이지를 요약해 돌려주는 도구로 읽었다면 인용 문장은 원문과 다를 수 있다 — 판정의 근거가 되는 문장은 원문(저장된 HTML · 소스 · 다시 열기)과 대조한 뒤에 `확인` 으로 쓴다.

---

## 1. 입력

| 항목 | 필수 | 메모 |
|---|---|---|
| 공고 링크 또는 공고 본문 | **필수 (이것 하나면 시작한다)** | 링크를 못 읽으면 본문을 붙여 달라고 한다 |
| 지원하는 사람의 목표 | 선택 | 직무 · 연차 · 관심 영역. 없으면 공고 기준으로만 정리 |
| 이미 아는 링크 | 선택 | 회사 소개 · 기술 블로그 · 발표 · 기사 |
| 결과물 폴더 | 선택 | **어느 경로든 된다.** 처음 만들 때 묻고, 답이 없으면 `./career-next/<회사-슬러그>/` 를 제안한다. 회사별 폴더를 이미 쓰고 있으면 그 안의 `career-next/` 를 제안한다 |

공고가 여러 개면 **회사 하나 = 폴더 하나**, 같은 회사의 다른 포지션은 같은 폴더 안 `profile-<포지션>.md` 로 나눈다.

## 2. 하는 일 (순서대로)

1. **공고 읽기** — 웹 페이지를 읽는 도구가 있으면 쓰고, 동적 페이지라 못 읽으면 본문을 받는다.
2. **공고에서 뽑기** — 아래 프로필 틀의 칸을 공고 문장으로 채운다. 공고에 없는 칸은 비워 두고 `열린 질문` 으로 옮긴다.
3. **역추론** — "왜 이 요건을 적었나" 를 2~4줄로 미루어 본다 (예: 대규모 트래픽 + Kafka + 정산 → 이벤트 기반 정산 파이프라인을 운영 중일 것). 전부 `추정` 라벨.
4. **회사 정보 모으기** — 공식 출처를 먼저: 회사 소개 · 기술 블로그 · 공개 발표 · 채용 페이지의 팀 소개 → 그다음 기사. 링크는 실제로 열어 보고, 링크마다 **수집일과 한 줄 요약**.
5. **시험 형식 묻기** — 공고에 시험 단서가 있든 없든 지원하는 사람에게 먼저 묻는다: *"시험 형식을 알고 있나요? (안내 메일 · 공지 · 전에 본 경험)"*
   - **안다** → 플랫폼 · 시간 · 문항 구성(코딩 · 단답 · 서술형 · 과제) · 쓰는 언어 · 허용 도구(검색 · IDE)를 그대로 적는다. `pretest` 가 이 형식과 비슷하게 준비한다.
   - **모른다** → 열린 질문으로 방향을 잡는다: 코딩만인가, 지식 문항(단답 · 서술형)도 있나, 과제형인가 · 대략 몇 분인가 · 어떤 언어로 푸나 · 검색 · IDE 를 쓸 수 있나. 답이 없는 칸은 `가정` 으로 적고, `pretest` 가 흔한 구성에서 시작해 형식이 알려지면 고친다.
   - **답을 받을 수 없으면** (지원자가 자리에 없는 실행 등) 이 질문들을 `열린 질문` 에 그대로 적고, 공고 · 회사 공식 채용 페이지(FAQ 포함)의 문장만으로 칸을 채운 뒤 나머지는 `가정` 으로 두고 진행한다.
6. **결과물 쓰기** — `profile.md` 와 `links.md` 를 만들고, 다음 한 걸음을 제안한다.

## 3. 결과물

### `profile.md` 틀

```markdown
# <회사> · <포지션>
> 한 줄 요약 — 이 포지션이 하는 일을 한 문장으로

## 포지션
연차 · 고용 형태 · 근무지 · 마감일 (공고 문장 그대로, 출처)

## 주요 업무
- (공고 문장)

## 요구 역량
| 구분 | 내용 | 출처 |
|---|---|---|
| 필수 | | 공고 |
| 우대 | | 공고 |

## 기술 스택
언어 · 프레임워크 · 데이터 · 인프라 · 협업 도구 (공고 + 공식 출처)

## 업무 영역 (도메인)
예: 주문 · 결제 · 정산 · 실시간 시세 · 알림

## 채용 절차와 시험 형식
절차: 서류 → … (공고)
시험: 플랫폼 · 시간 · 문항 구성 · 언어 · 허용 도구
형식 출처: 안내 메일 · 공고 · 회사 공식 채용 페이지(FAQ) · 지원자 기억 · 가정 중 무엇인지

## 역추론 (추정)
- 이 팀이 지금 풀고 있을 문제 2~4줄

## 열린 질문
- 공고로는 알 수 없어 확인이 필요한 것 (시험 형식 · 팀 구성 · 기술 스택 세부 …)

## 출처
links.md 참고
```

### `links.md` 틀

| 링크 | 종류 | 수집일 | 열어 봄 | 한 줄 요약 |
|---|---|---|---|---|
| | 공고 · 회사 소개 · 기술 블로그 · 발표 · 기사 · 지원자 링크 | YYYY-MM-DD | 확인 · 요약 열람 · 미확인 | |

`지원자 링크`(이력서 · 포트폴리오 속 GitHub · 블로그)는 resume 단계가 열어 보고 같은 표에 더한다. 열지 않은 링크는 따로 표를 두고 이유를 적는다.

## 4. 다음 한 걸음

정리가 끝나면 둘 중 하나를 제안한다.

- **이력서가 있거나 쓸 차례** → `career-next:resume` (프로필의 요구 역량과 이력서를 맞춘다)
- **시험이 잡혀 있거나 절차에 시험이 있음** → `career-next:pretest` (시험 형식 · 열린 질문을 이어받는다)

## 5. 하지 않는 것

- 출처 없는 사실을 쓰지 않는다. 연봉 · 내부 사정 같은 풍문은 넣지 않는다.
- 로그인이 필요한 페이지, 개인 정보, **유출된 시험 문제 · 기출 공유 자료는 모으지 않는다** (지원자가 동의한 시험 보안 서약과 부딪힐 수 있다).
- 공고를 길게 베끼지 않는다. 칸마다 필요한 문장만, 출처와 함께.
