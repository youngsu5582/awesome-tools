# 채점 기준

## 주관식 — 칸마다 ○ △ ×

| 표시 | 점수 | 언제 |
|---|---|---|
| ○ | 1 | 묻는 것을 빠짐없이, 동작 · 숫자 · SQL 까지 맞게 |
| △ | ½ | 방향은 맞지만 마지막 한 단계(정확한 동작 · 이유 · 숫자)가 빠지거나 틀림, 또는 조건 단어(각각 · 그대로 · 계산으로)를 일부 놓침 |
| × | 0 | 틀렸거나 비웠거나, 묻는 조건을 어김 |

문항 점수 = 칸 점수의 평균. 틀린 칸에는 **모범답안 3줄 이내**를 붙인다.

## 서술형 — 5항목 × 0 · 1 · 2

| 항목 | 0 | 1 | 2 |
|---|---|---|---|
| 전제 | 없음 | 있으나 막연함 | 숫자나 조건으로 박았다 (결정적인 숫자 한 줄) |
| 문제 | 엉뚱하거나 없음 | 증상만 적음 | 깨지는 지점을 단서를 인용해 정확히 |
| 선택 | 용어 나열 | 하나만 제시 | 대안 비교 + 고른 이유 + 대가 |
| 실패 | 없음 | 한 가지 경우만 | 재시도 · 타임아웃 · 부분 실패 · 결과 모름 중 2가지 이상 |
| 관측 | 없음 | "모니터링한다" | 무엇을 · 어떤 기준으로 보는지 구체적 |

쓰는 모양: 번호 붙인 짧은 문단 · 완결된 문장 · 600~1,000자. 화살표 나열은 "이유 없는 용어 나열" 로 읽힌다.

## 확인 원칙

- **실측과 추정을 나눈다.** 코드 답은 전수 탐색 · 무작위 비교로, 프레임워크 동작은 작은 실험 · 소스로 확인할 수 있으면 확인하고 `실측` 이라고 적는다. 확인 못 한 판단은 그렇다고 적는다.

## 채점 파일 형식 (`review.py` 의 `REVIEW` 또는 `review.json`)

예시: [`tools/examples/review.py`](../tools/examples/review.py)

| 키 | 내용 |
|---|---|
| `graded` · `took` | 채점 날짜 · 걸린 시간 |
| `totals` | `coding` · `short` · `essay` 합계 (문자열). 문제에 없는 절은 생략. 코딩 여러 문항이면 `coding` 은 점수의 합(생략하면 합을 계산) |
| `overview.left` · `overview.right` | 총평 (마크다운) |
| `short.q<번호>` | 칸마다 `{mark, comment, model?}` — 칸 수 = 묻는 것 수 |
| `essay.s<번호>` | `score` · `axes[[항목, 점수, 이유]]` · `good?` · `core` · `flow?` · `note?` |
| `coding` | 한 문항이면 객체, 여러 문항이면 **같은 모양의 객체 리스트**(순서 = 문항 번호). 객체 하나는 `score`(문항당 100점 만점) · `verdict` · `issues?[[o|t|x, 제목, 설명]]` · `diff?` · `alt?` · `altTitle?` · `checks?` · `tip?`. 문항 수와 리스트 길이가 다르면 생성기가 멈춘다 |

- 문제에 없는 절의 키(`short` · `essay` · `coding`)는 채점 파일에서 생략한다.
- 코딩 여러 문항 예시: [`tools/examples/review-coding-only.py`](../tools/examples/review-coding-only.py) (답: `answers-coding-only.md`)
- 내 답(`answers.md`)의 코딩은 한 문항이면 `### 코딩`, 여러 문항이면 `### 코딩 1`, `### 코딩 2` … 로 읽는다.
