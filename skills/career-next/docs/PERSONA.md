# PERSONA — 시간이 없는 이직 준비자

## 대표 페르소나

**서연 (가명), 2년차 백엔드 개발자, 재직 중.**

- 평일 저녁 1~2시간만 쓸 수 있다. 지원처는 서너 곳.
- 이력서에 한 일은 많다. 그런데 줄여 쓰다 보니 **"무엇을 했나" 만 남고 "왜 그렇게 골랐나" 가 빠졌다.**
- 이력서의 링크 몇 개는 오래전에 쓴 글이라, 지금 이력서 문장과 내용이 조금 어긋난다는 걸 모른다.
- 서류를 통과하면 온라인 시험이 있다. 형식은 안내 메일 몇 줄로만 안다.
- 피드백은 위로보다 **떨어질 이유**를 먼저 알고 싶다.

> 서연의 진짜 고민은 "이력서 괜찮아요?" 가 아니라
> **"이 회사 서류를 통과하나? 남은 2주를 어디에 써야 하지?"** 이다.

## 페인포인트 (결정 순간 중심)

| 순간 | 혼잣말 | 기존 도구의 실패 |
|---|---|---|
| 공고를 받았을 때 | "Kafka 랑 정합성을 왜 이렇게 강조하지?" | 공고 요약만 해 주고, 요건 뒤의 이유와 확인할 질문은 남기지 않는다 |
| 이력서 제출 전 | "이거 그대로 내도 되나?" | "전반적으로 좋습니다" + 일반론. 회사 기준 판정도, 링크 확인도 없다 |
| 시험 2주 전 | "문제를 더 풀어야 하나, 서술형을 써 봐야 하나" | 문제 은행만 준다. 형식 · 시간 · 약점에 맞춘 계획이 없다 |
| 시험 전날 | "뭘 다시 보지?" | 다 다시 본다. 자주 틀린 것 · 실수 방지가 한 장으로 없다 |

## 대표 시나리오

### 시나리오 A — 공고 + 이력서, 시험 2주 전 (TC1 · TC2 · TC4)
공고 링크와 이력서 PDF 가 있고, 75분 시험(코딩 1 · 주관식 5 · 서술형 2, 검색 불가)이 2주 뒤다.
→ intake 로 프로필 → resume 으로 판정 · 수정안 → pretest 로 진단 · 모의 2회 이상 · 마지막 한 장.

### 시나리오 B — 시험 형식을 모르고, 이력서도 아직 없다 (TC3 · TC5)
공고만 있다. intake 가 시험 형식을 열린 질문 + 가정으로 남기고, resume 은 경험 재료를 묻는 데서 시작한다. 나중에 "코딩 3문항만" 이라고 알게 되면 다음 모의 회차부터 그 형식으로 바꾼다.

## 입력 스키마 (Canonical Input Schema)

모든 단계가 이 키를 기준으로 묻고 기록한다. 없는 값은 묻거나 `가정` 으로 적는다.

```yaml
posting: <공고 URL 또는 본문>           # 필수 (intake)
target:                                 # 선택
  role: backend
  years: 2
  interests: [payments, data-consistency]
resume: <PDF · Markdown · 텍스트 · 공개 링크>   # 선택 (없으면 경험 재료를 묻는다)
materials: [portfolio, repos, posts]    # 선택 — 경험 재료
submitted: [resume]                     # 서류에 실제로 내는 것 — 판정 근거는 이것뿐
exam:                                   # pretest
  known: true                           # false 면 아래는 가정
  platform: <온라인 시험 플랫폼>
  minutes: 75
  sections: { coding: 1, short: 5, essay: 2 }
  language: java
  tools: { search: false, ide: false }
  date: 2026-11-21
daily_hours: 1.5
output_dir: ./career-next/acme/         # 처음에 묻는다
tone: cold                              # 기본. 지원자가 바꿀 수 있다
```
