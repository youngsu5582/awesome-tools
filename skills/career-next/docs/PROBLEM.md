# PROBLEM — 무엇을 닫는 팩인가

## 한 문장 문제

> 공고 하나를 받은 지원자가 회사 조사 · 이력서 · 시험 준비를 **따로따로** 하다 보니,
> 이력서는 공고와 맞물리지 않고, 자기 이력서는 후하게 읽히고,
> 시험은 문제만 많이 풀고 실제 형식 · 시간 배분 연습 없이 들어간다.

career-next 는 공고에서 뽑은 **지원 프로필 한 장**을 세 단계가 이어 쓰게 해서, 셋을 같은 기준(이 회사 · 이 직무)에 묶는다.

---

## 누구를 위해 / 어떤 순간에 / 어떤 결정을

| 축 | 내용 |
|---|---|
| **누구를 위해** | 1~5년차 개발자, 특히 재직 중에 이직을 준비하는 사람 — 시간이 적고, 지원처가 여러 곳이고, 공고마다 이력서를 새로 볼 여유가 없다 |
| **어떤 순간에** | 공고를 받은 직후 ~ 서류 제출 전, 그리고 서류 통과 뒤 ~ 시험 전날 |
| **어떤 결정을** | ① 이 공고가 실제로 무엇을 찾나 ② 내 경험 중 무엇을 위로 올리고 무엇을 뺄까 ③ 남은 날을 어떤 연습에 쓸까 |

---

## 지금 방식의 한계

1. **흩어진다.** 공고 분석 · 이력서 · 시험 준비가 다른 문서와 다른 대화에 있다. 공고의 요구 역량이 이력서 수정과 시험 소재로 이어지지 않는다.
2. **후하게 읽힌다.** 이력서 피드백이 "좋은 이력서지만…" 으로 시작해 일반론으로 끝난다. 이 회사 면접관이 통과시키나가 아니라, 일반적으로 좋은가를 묻는다.
3. **근거를 아무도 열어 보지 않는다.** 면접관은 링크를 누른다. 링크 글이 이력서의 주장과 어긋나도, 숫자에 확인 방법이 없어도 지원자는 모른다.
4. **시험 준비가 "많이 풀기" 로 끝난다.** 실제 형식 · 시간 배분 · 빈칸으로 남기는 실수 같은 시험장 실패는 연습되지 않는다.
5. **모의고사를 같은 대화에서 만들면 문제를 미리 본다.** 그러면 모의고사가 아니다.

## 이 팩이 하는 일

| 단계 | 하는 일 | 핵심 장치 |
|---|---|---|
| `intake` | 공고 → 지원 프로필 · 링크 목록 · 시험 형식 | 확인 · 추정 · 미확인 라벨, 링크는 실제로 열어 봄, 시험 형식은 먼저 묻기 |
| `resume` | 프로필 기준으로 이력서 방향 · 수정안 · 면접관 시점 피드백 | "실제 한 일" 압축을 판단보다 먼저, 낙관 경계, 판정 경계 표, 냉정한 말투 |
| `pretest` | 시험 형식 고정 → 진단 → 모의고사 → 채점 → 마지막 한 장 | 구간표 한 줄, 출제와 풀이 분리, ○△× · 서술형 5항목, 실측 |
| `guide` | 어디서 시작하고 어디까지 왔는지 | 상황표 → 한 걸음 |

## 하지 않는 일

- 이력서를 통째로 대신 쓰기, 지원자끼리 비교 · 순위, 합격 예측
- 유출된 시험 문제 · 기출 공유 자료 모으기, 시험 시간 중 돕기
- 연봉 · 내부 사정 같은 풍문
- 면접 준비 — 다음 단계로 남겨 두었다 (지금은 `feedback.md` 의 면접 질문 후보가 재료)
