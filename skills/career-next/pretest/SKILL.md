# pretest — 시험 형식에 맞춘 진단 · 모의고사 · 채점

시험 대비는 많이 푸는 게 아니라 **약점을 찾고, 실제와 같은 형식 · 같은 시간 안에 꺼내 보는 것**이다.
이 단계는 형식을 고정하고 → 진단으로 약점을 찾고 → 모의고사를 돌리며 약점이 줄었는지 숫자로 본다.

> **실측과 추정을 나눈다.** 모범답안의 동작 · 숫자는 작은 실험 · 소스 · 전수 비교로 확인할 수 있으면 확인하고 `실측` 이라고 적는다. 확인 못 한 것은 그렇다고 적는다.
> **채점은 냉정하게** — `career-next:resume` 의 말투 절과 같다. 맞은 척 넘어가는 △ 하나가 시험장에서 × 가 된다.

---

## 1. 입력

| 항목 | 필수 | 메모 |
|---|---|---|
| 시험 형식 | **필수** | `profile.md` 의 「채용 절차와 시험 형식」. 없으면 intake 5단계 질문(플랫폼 · 시간 · 문항 구성 · 언어 · 허용 도구)을 여기서 한다 |
| 시험 날짜 | 권장 | 남은 날로 계획 크기를 정한다 |
| 하루에 쓸 수 있는 시간 | 권장 | 없으면 평일 1~2시간으로 가정하고 적는다 |
| 지원 프로필 | 권장 | 기술 스택 · 업무 영역 → 문항 소재 |
| 이력서 피드백 | 선택 | `feedback.md` 의 「정말 없는 것」 갭 → 진단 소재 |

형식이 `가정` 이면 흔한 구성(코딩 + 지식 문항)에서 시작하고, 형식이 알려지는 날 모의고사 형식부터 고친다.

## 2. 하는 일 (순서대로)

1. **형식 고정** — 시간 · 문항 구성 · 언어 · 허용 도구를 **구간표 한 줄**로 바꾼다. 예: 75분 = `훑기:3,코딩:20,주관식:25,서술형:25,제출:2`. 마지막 구간은 꼭 **제출 전 훑기**(빈 칸 확인)로 둔다. 시험에서 검색 · IDE 를 못 쓰면 연습도 자동완성 · 검색 없이 한다.
2. **계획** — 남은 날 × 하루 시간으로 짠다: 진단 1회 → (서술형 · 코딩 연습) → 모의고사 **최소 2회**(1회 = 형식 적응, 2회 = 고친 게 반영됐나) → 마지막 한 장. 시험 이틀 전부터는 새 자료를 만들지 않고 틀린 것만 다시 본다. 계획이 밀리면 뺀 것을 「시험 뒤로」 목록에 옮겨 적는다 — 몰래 줄이지 않는다.
3. **진단** — 스택 · 업무 영역 · 갭에서 소재를 골라 주관식 모양(상황 → 묻는 것 ①②③ → 보려는 것, [MOCK_FORMAT](../docs/MOCK_FORMAT.md))으로 10~15문항. 주관식만 있는 문제 파일이라 시험 화면(7단계 도구)으로 시간을 재며 풀게 하거나, 문항 아래 답 칸에 쓰게 한다. 채점은 [RUBRIC](../docs/RUBRIC.md) 의 ○△×. 채점 뒤 **약점 지도**를 만든다:
   | 영역 | 문항 | ○△× | 어디서 멈췄나 |
   |---|---|---|---|
   "어디서 멈췄나" 는 한 줄로 — 예: *개념 이름에서 멈추고 실제 SQL · 숫자 · 동작으로 내려가지 않음*. 약한 영역 2~3개가 모의고사 소재의 절반을 차지한다.
4. **서술형 — 유형별 질문 하나** (서술형이 있을 때) — 3절의 다섯 유형을 하나씩, 유형마다 12분 안에 600~1,000자로 써 보고 5항목으로 채점한다.
5. **코딩 — 패턴 한 줄** (코딩이 있을 때) — 시험 언어로, 허용 도구 조건대로 푼다. 다 풀면 **패턴 한 줄**로 남긴다 (4절). 답이 맞았는지는 느낌이 아니라 **전수 탐색 · 무작위 입력 비교**로 확인한다.
6. **모의고사 출제 — 서브에이전트가 쓴다.** 푸는 사람이 문제를 미리 보면 모의고사가 아니다. 대화에 문제 내용이 나오지 않게, 출제는 별도 에이전트에게 맡기고 이렇게 지시한다:
   - 형식(구간표 · 문항 수 · 언어)과 소재(프로필의 스택 · 업무 영역, 약점 지도 상위 영역 비중 ↑)
   - 겹치면 안 되는 것: 진단 · 이전 회차 문항 파일 경로
   - 문제 파일은 MOCK_FORMAT 그대로 `mock-N.md`, 채점 포인트는 따로 `mock-N-key.md` (채점할 때만 연다)
   - 코딩을 공개 문제에서 고르면 링크를 실제로 열어 확인한다
   - **보고에는 문항 수와 파일 경로만** — 제목 · 소재 · 힌트도 쓰지 않는다

   별도 에이전트를 띄울 수 없는 환경이면, 위 지시를 새 대화창에 붙여 출제를 맡기고 파일만 받아 온다.
7. **시험 화면** — `tools/build_mock_sheet.py` 로 HTML 한 장을 만든다 (구간 알림 · 소리 · 시간이 끝나면 잠금 · 답을 `answers.md` 형식으로 복사). 문제 파일에는 실제 시험에 있는 절만 넣는다 — 코딩 여러 문항 · 코딩만 · 주관식만도 된다. 구간표는 1단계의 한 줄을 `--schedule` 로, 코드 언어는 `--lang` 으로 준다. 실제 시험 시간 그대로, 한 번에 앉아서 푼다. 쓰는 법은 [tools/README](../tools/README.md).
8. **채점** — 지원자가 붙여 준 `answers-N.md` 를 RUBRIC 대로 채점한다. 코딩은 전수 · 무작위 비교, 주관식은 칸마다 ○△× + 틀린 칸에 모범답안 3줄, 서술형은 5항목. 모범답안 속 동작은 실측할 수 있으면 실측한다. 채점 파일(`review-N.py`)로 `tools/build_review.py` 를 돌려 **채점 화면**을 만든다.
9. **회차 기록** — `scores.md` 에 한 줄씩 쌓고 약점 지도를 고친다:
   | 회차 | 날짜 | 코딩 | 주관식 | 서술형 | 5항목 평균 (전제 · 문제 · 선택 · 실패 · 관측) | 다음 회차에 고칠 것 |
   |---|---|---|---|---|---|---|
   5항목 평균에서 가장 낮은 항목이 다음 회차의 연습 거리다.
10. **마지막 한 장** — 시험 전날 볼 `final.md` (5절).

## 3. 서술형 — 유형마다 질문 하나

서술형 문제는 대개 다섯 유형 중 하나다. 첫 30초에 유형을 고르고, 그 유형의 **질문 하나**를 문제에 던지면 쓸 거리가 나온다.

| 유형 | 알아보는 단서 | 던질 질문 |
|---|---|---|
| T1 장애 · 원인 분석 | 증상 · 지표 · 로그가 주어진다 | **이 단서는 무엇을 지우나?** — 단서 하나마다 지워지는 원인 후보를 적는다 |
| T2 대규모 · 성능 | 사용자 수 · 초당 요청 · 데이터 크기 | **숫자를 계산하면 어디가 넘치나?** — 계산을 먼저 쓰고 넘치는 곳부터 |
| T3 배포 · 변경 · 이전 | 스키마 변경 · 버전 교체 · 데이터 이전 | **옛 것과 새 것이 같이 돌 때 무엇이 깨지나?** |
| T4 돈 · 수량 | 결제 · 잔액 · 재고 · 포인트 | **어떤 민원이 들어올까?** — 아래 일곱 가지 |
| T5 민감 데이터 | 개인 정보 · 인증 · 로그 | **이 데이터가 어디까지 흘러가나?** — 저장 · 로그 · 캐시 · 외부 전송 · 백업 · 삭제 |

**T4 민원 일곱 가지와 장치**

| 민원 | 장치 |
|---|---|
| 두 번 빠져나갔어요 | 유일 제약(UNIQUE) · 요청 전에 행을 미리 만들기 |
| 됐는지 몰라요 | 상태를 두고 조회로 확정한다 — 결과를 모를 때 다시 보내지 않는다 |
| 마이너스가 됐어요 | 조건부 UPDATE (`잔액 >= 금액` 일 때만) |
| 1원이 안 맞아요 | 정수 · DECIMAL 과 반올림 규칙 |
| 언제 바뀐 거죠 | 덮어쓰지 않고 쌓기만, 취소는 반대 기록 |
| 아무도 몰랐어요 | 대사(양쪽 합계 맞춰 보기)와 알림 |
| 오늘 안에 돼요? | 처리량을 숫자로 계산 |

일곱 개를 다 쓰지 않는다 — **이 문제에서 특히 들어올 민원**이 함정이 숨은 곳이다.

**쓰는 모양** — 번호 붙인 짧은 문단, 완결된 문장, 600~1,000자. 화살표 · 용어 나열은 "이유 없는 나열" 로 읽힌다.

**15분 흐름** — 30초 유형 고르기 → 2분 문제 문장에 번호 매기기(묻는 것이 몇 개인지) → 숫자 먼저 계산 → 쓰기 → 마지막 1분 5항목(전제 · 문제 · 선택 · 실패 · 관측) 확인. 가장 자주 빠지는 건 **관측**(무엇을 어떤 기준으로 보나)과 **전제**(숫자 · 조건 한 줄)다.

## 4. 코딩 — 패턴 한 줄

푼 문제를 이름이 아니라 **다음에 꺼낼 한 줄**로 남긴다. 예:

| 패턴 한 줄 | 이런 문제에 |
|---|---|
| 안 고르는 경우를 하나 넣고, 마지막에 하나 뺀다 | 종류별로 0~1개 고르는 조합 수 |
| 둘만 비교하는 규칙을 정렬 기준으로 | 이어 붙여 가장 큰 수 만들기 |
| 시작 시각으로 정렬하고, 가장 먼저 비는 자리를 다시 쓴다 | 회의실 · 객실 배정 |
| 한쪽에 다 세어 두고 하나씩 옮긴다 | 배열을 둘로 나눠 양쪽 종류 수 비교 |
| 합은 매번 다시 세지 말고 바뀐 만큼만 갱신한다 | 두 큐 · 구간 합 맞추기 |

시험에서 검색 · 자동완성이 없으면, 자주 쓰는 표준 라이브러리 호출(정렬 기준 · 우선순위 큐 · 맵 기본값)을 손으로 한 번씩 쓴다.

## 5. 결과물

결과물 폴더(intake 와 같은 곳) 아래 `pretest/`:

| 파일 | 내용 |
|---|---|
| `plan.md` | 형식 · 구간표 · 날짜별 계획 · 「시험 뒤로」 목록 |
| `diagnostic.md` | 진단 문항 · 답 칸 · 채점 |
| `weakness.md` | 약점 지도 (회차마다 고친다) |
| `mock-N.md` · `mock-N-key.md` | 모의 문제 · 채점 포인트 (출제 에이전트가 씀 — **풀기 전에 열지 않는다**) |
| `mock-N.html` | 시험 화면 |
| `answers-N.md` | 내 답 (시험 화면의 「답안만 복사」) |
| `review-N.py` · `review-N.html` | 채점 · 채점 화면 |
| `scores.md` | 회차 기록 |
| `final.md` | 마지막 한 장 |

**`final.md` (마지막 한 장)** — 한 화면에 들어가게:
- 시험 형식 · 구간표 · 입실 전 할 일(안내 메일 기준)
- 서술형: 유형 질문 다섯 · 15분 흐름 · 내가 자주 빠뜨린 항목
- 약점 상위 3개와 각각 "이것만 기억" 한 줄
- 코딩: 패턴 한 줄 목록
- 실수 막기: 조건 단어(각각 · 그대로 · 계산으로 · 숫자로) 표시하기 · 모르면 아는 데까지라도 쓰기(부분 점수) · **제출 전 모든 문항 탭을 한 번씩 열어 빈 칸 0개 확인**

## 6. 다음 한 걸음

- 시험이 끝나면 → 면접 준비 단계 (`feedback.md` 의 면접 질문 후보 · 약점 지도 남은 것이 재료)
- 시험 형식이 새로 알려지면 → 1단계 형식 고정부터 다시, 다음 모의 회차에 반영

## 7. 하지 않는 것

- **실제 시험 문제 · 기출 공유 자료를 모으거나 소재로 쓰지 않는다.** 시험 뒤 기억나는 문항을 남기고 싶다면, 지원자가 동의한 시험 보안 서약을 먼저 확인하고 공개되지 않는 자리에만.
- **시험 시간 중에는 돕지 않는다.** 시험 중 질문이 오면 거절하고 끝난 뒤를 제안한다.
- 모의 문항을 풀기 전에 보여 주지 않는다 (출제 보고 · 진행 안내에도 문제 내용을 쓰지 않는다).
- 확인하지 못한 모범답안을 확인된 것처럼 쓰지 않는다.
